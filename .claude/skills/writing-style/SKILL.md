# 筆者の文体で書く

既存記事と LT 資料から抜き出した筆者の書き癖。
目指すのは「業務で触った技術を、体験ベースでざっくり共有する同僚の声」。整った解説記事ではなく、やってみた記録として書く。

## 手順

1. [references/examples.md](references/examples.md) を読み、実際の文章の温度感をつかむ
2. 素材を確認する。筆者の体験（なぜやったか・どこで嵌ったか・やってみてどう思ったか）が手元にあるか見る
   - 足りなければユーザーに聞く。聞けないときは創作せず、その位置に `{/* TODO: 〇〇の感想 */}` を置く
3. 「構成」「文体」に沿って書く。書き直しのときは事実・コード・リンクはそのまま残し、文体と流れだけを変える
4. 仕上げ: 本文を 1 行ずつ読み、「チェックリスト」の全項目を満たすまで直す

## 構成

- 導入は 2〜4 行。「いまのプロジェクトでは〜」「業務で〜していました」と状況から入り、困りごと・動機を一言添えてすぐ本題へ
- 見出しは `## ■ 〜`。中身がそのまま伝わる口語でよい（`## ■ w-screen と w-full でミスった`、`## ■ 一瞬だけライトモードで表示されてしまう`）
- 流れは「状況 → やったこと → 嵌ったところ → どう解決したか」。嵌りポイントと失敗談は記事の主役として扱う
- 自分が触った・嵌った範囲に絞る。周辺の詳しい説明は参考記事や公式ドキュメントへのリンクに任せ「詳細はこちらの記事に記載されているので割愛します」と書く
- 締めは短く、感想と次にやること（「〜していこうと思います」「まずは〜で使ってみて様子を見ようと思います」）。論点が多い記事だけ `## ■ まとめ` に箇条書き + 一言の感想

## 文体

### 文末とリズム

- ですます調がベース。句点「。」は付けない
- 1 文 1 行、段落は 1〜3 行で空行区切り（MDX の段落内改行は行末に半角スペース 2 つ。手順は tech-blog-writer の [blog-conventions.md](../tech-blog-writer/references/blog-conventions.md)）
- 文頭の接続は「なので、」「ただ、」「また、」「そこで」「とはいえ」「つまり、」「例えば」
- 確信度をそのまま出す。「〜と思います」「〜な感じです」「〜そうです」「〜らしいです」「おそらく」「〜はず」
- 手順は文を「〜して、」で切り、コードブロックを挟んで次の文につなぐ（「まずはインストールして、」→ コード →「css ファイルに追加します」）
- リストの前置きは「〜は以下です」「ざっくり以下です」「違いは以下」「以下のようにしました」

### 本音の差し込み

筆者らしさの核。整った説明の合間に、心の声を短く挟む。

- 半角括弧で補足や本音: `( 公式の Example がとても参考になりました )`、`(対応に自信はないけど自分のスマホで見る限りは大丈夫そう、、)`
- 言いよどみ・苦笑いは読点を重ねて「、、」「、、、」（「記事書ければ、、」「デフォルトになる、、はず」）
- うまくいった・助かったときに「！」「！！」（「無事に認証が通っていることを確認できました！！」「助かる！」）
- 心の声は常体で短く（「お！これこれ！」「どういうこと？状態に」「ほえ～～っと思ったのは」「ちゃんと理解して使わないとあかんなぁと思いました」）
- 密度は本音・「、、」・「！」それぞれ 1 セクションに 0〜1 回が目安。散らしてこそ効く

### 語彙

- よく使う: ざっくり / いい感じ / 嵌る（漢字） / ちょこちょこ / 地味に / ひとまず / 割と / なんとか / それっぽい / ミスる / 便利！
- ツールの動作は「〜してくれる」（「いい感じにハイライトしてくれる」「自動で切りかえてくれる」）
- 一人称は「自分」、評価は「個人的には」
- 参考にしたものには敬意を込める（「〜を参考にさせていただきました」「Hono 開発者様が公開している Example」）

### 表記

- 技術用語・製品名は英語のまま。コマンド・設定値・ライブラリ名はインラインコード
- 英単語・インラインコードの前後に半角スペース
- 括弧は半角 `( )`
- 注記は「※」、帰結や言い換えはネストした箇条書きで「⇒」
- 項目の説明は `**項目**: 説明`、理由や補足はネストした箇条書きで

## 置き換え表

AI が書きがちな言い回しは右側の言い方にする。

- 「本記事では〜を紹介します」 → 状況からいきなり入る
- 「〜について解説します」 → 「〜をまとめます」「手順を残します」
- 「〜しましょう」「ぜひ〜してください」 → 「〜すると良いかもしれません」「〜と思います」
- 「〜と言えます」「最大の魅力は〜」「非常に〜」 → 「〜な感じです」「〜が便利！」「とても〜」
- 「〜ではないでしょうか」 → 「〜と思います」
- 読者への問いかけで締める → 感想 + 次にやること
- メリット・デメリットの網羅 → 自分が使った・嵌った部分だけ
- 「…」 → 「、、」

## チェックリスト

- 句点「。」がない
- 1 文 1 行、段落は 3 行以内
- 導入が状況・動機から始まり 4 行以内
- 体験・感想はすべて素材かユーザーの発言に由来する（ないものは TODO コメント）
- 本音・「、、」・「！」がそれぞれ 1 セクション 0〜1 回
- 置き換え表の左側の言い回しがない
- 推測が推測の形で書かれている
- 英単語・インラインコードの前後に半角スペースがある
